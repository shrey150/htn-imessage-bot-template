One small agent. Your big idea.

OpenInstinct Lite keeps the useful core of the earlier OpenInstinct + Browserbase build: a message becomes a browser task, then a concise reply. Eve supplies the agent loop and channels. The official Browserbase extension supplies nine web tools.

You'll need Node.js 24, Git, and accounts for Browserbase and a model provider. Follow steps 1–4 for the terminal demo, then connect your Linq line in steps 5–6.

Start building while your number is being set up.

The terminal and headless command use the same agent as Linq. You can develop your whole browser flow before your line is ready.

Paste this into your coding agent. It points to the repo's setup contract, runs the real smoke test, and handles Eve's noninteractive setup flow.

01

Get the starter

Use the GitHub template button to create your own repo, or clone the starter directly. Install Node.js 24 first; npm comes with it.

TERMINAL 
git clone https://github.com/shrey150/openinstinct-lite.git
cd openinstinct-lite
npm ci

The repo already contains Eve's scaffold and the Browserbase extension. The lockfile pins the tested versions, so you can focus on your project.

02

Connect your accounts

Use two credentials for the terminal demo. Browserbase covers web tools and the browser model; AI Gateway covers Eve's reasoning model.

VARIABLEWHERE TO GET IT
BROWSERBASE_API_KEYBrowserbase project settings ↗
AI_GATEWAY_API_KEYVercel AI Gateway ↗

Inject credentials through your secret manager. For a local demo, the included Bash helper reads them in hidden prompts and keeps them in your current shell.

MACOS / LINUX / WINDOWS WSL 
bash
source scripts/keys.sh
npm run doctor

Keep using that shell for the next commands. The helper writes no keys to disk. Use Coder User Secrets on a Coder devbox, or your usual vault for persistent access.

What the accounts need

Browserbase access must support keep-alive sessions, which the official extension uses. Browser and model calls consume account credits. Eve also supports interactive /login; the doctor checks the explicit API-key path above.

03

Run your first browser task

Start with a tiny, repeatable task. This command asks Eve to create a Browserbase session, open a page, extract its heading, and close the browser.

LIVE SMOKE TEST 
npm run smoke
EXPECTED RESULT“Example Domain”
https://example.com

Check the answer and the session in your Browserbase dashboard. Then start a conversation or run another task from a script.

INTERACTIVE CHAT 
npm run dev
HEADLESS / CODING AGENT 
npm run --silent ask -- "Open news.ycombinator.com in a browser. Return the first three story titles with links, then close the browser."

The headless command returns clean Eve JSON, with SDK diagnostic logs removed. The smoke test isolates the two documented credentials and fails on tool errors, including recovered fallbacks. Exit 0 means the invocation completed, 1 means failure, and 3 means input or authorization is pending. Inspect the answer to confirm the task itself succeeded.

Continue a headless conversation

Keep the previous result in a private temporary file outside the repo. Send that JSON on stdin to resume the same session:

FOLLOW-UP 
npm run --silent ask -- --resume "Summarize those in one sentence" < /path/to/previous-result.json
04

Make it your hack

Open agent/instructions.md. Replace the last section with a specific audience, task, and output format. Keep your first demo narrow enough to explain in one sentence.

CAREERS
Internship scout

Three public roles matching a skill and city, with application links.

CAMPUS LIFE
Weekend planner

Three things to do near Waterloo, backed by current source pages.

SHOPPING
Product researcher

Compare three options against a budget and return listing links.

LEARNING
Paper companion

Turn an article or project page into three useful takeaways.

THE FILES YOU'LL TOUCH MOST 
agent/
  instructions.md             # Your idea and reply format
  agent.ts                    # Reasoning model and limits
  extensions/browserbase.ts   # Browser model and timeout
  channels/eve.ts             # Authenticated HTTP entry
  channels/linq.ts             # Native Linq adapter, ready to configure

Optional shell tools are disabled. Browserbase supplies search, fetch, navigation, observation, actions, extraction, and session management. The prompt steers toward research; add enforced tool approvals before introducing purchases or other commitments.

05

Give your agent a number

Linq brings the same agent into iMessage and SMS. Choose one setup route below. Both use Eve's native Linq channel.

Building at Hack the North?

Sign up for Linq’s free seven-day sandbox with your school email. Text Activate to the number shown in your dashboard from your testing phone. Save the API key in your secret manager, then use the included adapter setup below. You already have a line; no second line or connector setup is needed.

Guided setup with Vercel Connect

NATIVE SETUP 
npx eve link
npm run linq

This replaces the included portable channel with a managed connector. Use this before customizing the channel, or save your changes first. Choose Vercel Connect in the setup flow, create or connect your Linq account, and select a line. Eve manages the connector credentials and webhook. Follow the remaining setup steps it reports.

A phone number is an account prerequisite.

Line availability and provisioning depend on your Linq account. If your event provides a line and credentials, use the portable route below. The terminal demo stays available while you wait.

Setting up Linq with a coding agent
NONINTERACTIVE SETUP 
npx eve add channel/linq --non-interactive --overwrite

Exit 2 means setup needs an answer or a prerequisite. Read the final NDJSON event and follow next.command. Supply non-secret answers only. A deployment may be required to finish setup.

Already have a Linq key and a hackathon line?

The repo already includes agent/channels/linq.ts. Configure it with credentials from your secret manager; no adapter installation is needed.

VARIABLEVALUE
LINQ_API_KEYLinq Partner API v3 key
LINQ_WEBHOOK_SECRETSecret from the webhook subscription
LINQ_ALLOWED_SENDERSYour team’s sender phone numbers, comma-separated in E.164 format

After deployment, create a Linq webhook subscription for the endpoint below, filtered to your agent's line. Subscribe to message.received, reaction.added, and reaction.removed.

WEBHOOK URL 
https://YOUR-APP.vercel.app/eve/v1/linq

Save the returned signing secret in your host's encrypted environment and redeploy. It is shown only at creation. The sender allowlist contains your own phone numbers, not the agent's receiving number.

For local keys, run source scripts/keys.sh --linq, then npm run doctor -- --linq. The direct adapter verifies signatures and ignores senders outside the list. Use a production-mode server for any public tunnel; development mode trusts development HTTP traffic.

06

Deploy it. Text it.

In your linked Vercel project, add BROWSERBASE_API_KEY to the encrypted Production environment. Add the three Linq variables if you chose the portable route.

Eve can use Vercel project OIDC for AI Gateway when your team has model access. Otherwise, set AI_GATEWAY_API_KEY on the project too.

VALIDATE & DEPLOY 
npm run check
npm run build
npm run test:server
npm run deploy
Noninteractive deployment
CODING AGENT / CI 
npx eve deploy --project YOUR-PROJECT --non-interactive --yes
HEALTH CHECK 
curl https://YOUR-APP.vercel.app/eve/v1/health
Reference deployment

The deployed backend health check returns ready. A Linq sandbox line is connected and restricted to configured senders. The first complete phone test is still pending; see verification. Use your own deployment for your project.

Now text your Linq line from a configured sender:

YOUR FIRST TEXTOpen example.com in a browser, tell me its heading, and close the browser.

When Example Domain arrives on your phone, the whole chain works: Linq → Eve → Browserbase → Linq. Try your own project prompt next.

Check delivery, not just health.

Health confirms the web service. The actual text reply confirms messaging. Direct Linq webhooks must reach the endpoint through any deployment protection; keep Eve's production HTTP authentication enabled.

Keep building

Doctor passes, but the model or browser fails

Doctor checks variable presence, not credits or permissions. Check AI Gateway access to the configured Eve model, then Browserbase credits and keep-alive support. The Browserbase key covers the browser model; Eve's model has its own authentication.

Vercel linking asks for a scope

For noninteractive setup, run npx vercel link --project YOUR-PROJECT --scope YOUR-TEAM --yes, then retry Eve from the linked directory. Use a team where you can create projects.

My phone doesn't get a reply

Check Linq's webhook delivery logs, subscribed events, assigned line, signing secret, and deployment protection. For the portable adapter, confirm your sender phone is in LINQ_ALLOWED_SENDERS. Unsigned requests should be rejected.

I want memory, reminders, or a web UI

Keep your first demo focused. This starter uses Eve's conversation history but adds no permanent memory store or scheduler. When those features become part of your project, look for an existing integration in Eve's registry or start from one of Eve's templates.
